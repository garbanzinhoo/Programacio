Paquets en Java

Paquets

Per desenvolupar projectes grans que utilitzen moltes classes, és molt útil agrupar-les en paquets.
Naturalment, les classes s'hauran d'agrupar seguint criteris de similitud.

Els paquets faciliten la feina quan es treballa en equip perquè permeten que els diferents programadors treballin simultàniament i de forma independent en diferents parts del programa.

En les empreses tambè són útils per reaprofitar el codi generat, creant llibreries o biblioteques de classes que es poden utilitzar en múltiples projectes.

Finalment, es poden aprofitar paquets generats per tercers o els mateixos paquets estàndard de Java.

Un petit inconvenient de reutilitzar els paquets i les classes és que pot ser que en un projecte determinat no es necessitin tots els mètodes que inclouen, però normalment no és un problema rellevant.

Organització dels arxius de les classes d'un paquet

Normalment, quan es crea un nou projecte en un IDE, es munta una estructura bàsica de carpetes.

Per exemple, en IntelliJ, si es crea un projecte indicant com a Base Package cat.sapa.uf2, es crea la següent estructura:

  • cat.sapa.uf2
    • src
      • cat
        • sapa
          • uf2

Per afegir un paquet es pot seleccionar l'opció del menú principal File → New → Package.

Per exemple, es podria crear el paquet cat.sapa.uf2.arrays per ficar a dins les classes amb mètodes estàtics per processar arrays (IntegerArrays i StringArrays).

Això crearà una nova carpeta arrays dins de la carpeta cat.sapa.uf2\src\cat\sapa\uf2.

Els noms dels paquets s'acostumen a posar en minúscules seguint una notació semblant a una URL.

Afegir classes a un paquet

Al crear una classe dins d'un paquet, l'IDE automàticament afegeix l'identificador a la primera línia.

Per exemple, si es crea la classe IntegerArrays dins del paquet cat.sapa.uf2.arrays, al principi de l'arxiu IntegerArrays.java afegirà:

package cat.sapa.uf2.arrays;

Per poder utilitzar els mètodes estàtics d'una classe que es troba en un altre paquet, s'han de definir els mètodes com a publics:

public static funcio() {
    // Codi de la funció
}

Es pot repetir el nom d'una classe sempre que estiguin en paquets diferents, però sempre és millor no fer-ho per evitar confusions.

Utilitzar les classes d'un paquet

Si es vol utilitzar les classes d'un paquet en una altra classe cal importar-les.
La forma més recomanable és utilitzar la comanda import per cada classe:

import cat.sapa.uf2.arrays.IntegerArrays;
import cat.sapa.uf2.arrays.StringArrays;

Si es vol utilitzar totes les classes d'un paquet, no cal posar-les una a una:

import cat.sapa.uf2.arrays.*;

La següent comanda només importa les classes que hi ha directament dins del paquet cat.sapa.uf2, no les classes del subpaquet cat.sapa.uf2.arrays.

import cat.sapa.uf2.*;

També es pot utilitzar el nom qualificat (complet) d'una classe si aquesta només s'utilitza una vegada, però no és gaire habitual ni recomanable:

cat.sapa.uf2.IntegerArrays.ordenar(array);

Executar un projecte amb paquets

Els IDEs executen automàticament el projecte, tingui els paquets que tingui, però si es vol executar des de consola, cal fer el següents passos:

  1. Obrir un terminal i anar al directori principal del projecte compilat.
    En el cas de IntelliJ, si el projecte s'anomena TestFuncions, el directori serà semblant a IdeaProjects\TestFuncions\out\production\TestFuncions.
  2. Executar la classe principal amb el programa java indicant la ruta fins la classe principal:
    java cat/sapa/uf2/TestFuncions o java cat.sapa.uf2.TestFuncions.

En Windows, els directoris es mostren separats amb contrabarra (\); en Linux s'utilitza la barra (/).
Però amb la comanda java sempre s'ha d'utilitzar la barra (/) o el punt (.) per indicar la ruta de la classe principal.

Comandes per navegar pels directoris

  • tree: mostra l'arbre de directoris que hi ha dins del directori actual.
  • cd directori: entra en un directori que és fill del directori actual.
  • cd ..: torna al directori pare del directori actual.

Creació d'un arxiu executable JAR

Quan un projecte conté diversos paquets i/o classes, el procés d'instal·lació en altres màquines pot ser complicat i és fàcil cometre algun error, per exemple, oblidar-se algun arxiu.

Tampoc és fàcil executar-lo (encara que es pot automatitzar el procés).

Per facilitar aquests processos, es pot crear un arxiu JAR que contindrà tots els arxius necessaris.

En IntelliJ, per crear un arxiu JAR cal seguir els següents passos:

  1. Crear la configuració per generar l'arxiu JAR
    1. En el menú principal, seleccionar File → Project Structure...
    2. En l'apartat Artifacts, afegir (+) JAR → From modules with dependencies...
    3. Triar la classes principal, per exemple TestFuncions i guardar.
  2. Crear l'arxiu JAR
    1. En el menú principal, Build → Build Artifacts...
    2. Seleccionar el JAR, per exemple TestFuncions:jar i Build o Rebuild

L'arxiu JAR no es genera automàticament: si es fa algun canvi en el codi, cal tornar-lo a construir (Build → Build Artifacts... → Rebuild)

Executar un arxiu JAR

Des del mateix IDE

En IntelliJ, menú principal Run → Run... → TestFuncions.jar

En la barra d'eines superior hi ha un deplegable on es pot triar si es vol executar la classe o l'arxiu JAR.
Cal vigilar perquè si està seleccionat el JAR, els canvis que es facin en el codi no actualitzen el JAR quan es clica el botó d'executar (només reconstrueix les classes).

Des de la consola
  1. Obrir un terminal i anar al directori on s'ha creat l'arxiu JAR, per exemple, IdeaProjects\TestFuncions\out\artifacts\TestFuncions_jar.
  2. Executar l'arxiu JAR amb la comanda java -jar TestFuncions.jar.

Instal·lar el programa JAR en altres màquines

Només cal copiar l'arxiu JAR en un directori qualsevol i crear un enllaç amb la comanda per executar-lo.
