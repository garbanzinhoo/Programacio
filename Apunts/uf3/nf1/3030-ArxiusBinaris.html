Arxius orientats a bytes

En aquests arxius, a més de caràcters, també s'emmagatzemen directament valors en binari.

Exemples d'aquests tipus de fitxers:

  • Programes: .exe, .bin.
  • Arxius de processadors de textos o imatges: .doc, .pdf, .bmp, .png, .jpg.
  • Arxius de música i vídeos: .mp3, .oog, .wav, .mpeg, .mp4, .avi.

Degut a que no cal convertir la informació a binari o des de binari, el processament és més ràpid i acostumen a necessitar menys espai.
Per exemple, el número -4611686018427387903, ocuparia 20 caràcters (40 bytes) en mode text, però només 64 bits (8 bytes) en mode binari.

A més, si totes les dades són del mateix tipus o es coneix l'estructura del fitxer, es pot accedir a qualsevol dada de forma molt ràpida (sense haver de llegir totes les anteriors), i es pot modificar una dada sense haver de reescriure tot el fitxer.

Un inconvenient és que no es pot veure la informació obrint-los amb un editor de text pla: s'han d'obrir utilitzant programes específics.

Llegir i escriure un arxiu binari

Amb els arxius binaris, cal utilitzar la classe RandomAccessFile, que permet llegir i escriure a la vegada, llegir i escriure dades en format binari, i accedir a qualsevol posició de l'arxiu.

Al crear un objecte d'aquesta classe, cal passar-li un objecte de tipus File amb la ruta de l'arxiu i un String indicant el mode d'accés:

  • Només lectura (r): cal que l'arxiu existeixi.
  • Lectura i escriptura (rw): si l'arxiu no existeix, es crea; si existeix, només l'obre (no l'esborra).

File f = new File("./Proves/arxiu.bin");
RandomAccessFile raf = new RandomAccessFile(f, "rw");

Per llegir les dades de l'arxiu es poden utilitzar les següents comandes:

  • readByte(): llegeix un byte, valors entre -128 i +127.
  • readShort(): llegeix 2 bytes, un enter curt, valors entre -32768 i +32767.
  • readInt(): llegeix 4 bytes, un enter, valors entre Integer.MIN_VALUE i Integer.MAX_VALUE.
  • readLong(): llegeix 8 bytes, un enter llarg, valors entre Long.MIN_VALUE i Long.MAX_VALUE.
  • readFloat(): llegeix 4 bytes, un valor real de precisió normal.
  • readDouble(): llegeix 8 bytes, un valor real de precisió doble.
  • readBoolean(): llegeix 1 byte, un valor booleà (0 o 1).
  • readChar(): llegeix 2 bytes (Java treballa amb caràcters Unicode).

Cal saber el tipus de dada que s'està llegint. En cas contrari es poden produir resultats inesperats.

Per escriure es poden utilitzar les comandes equivalents: writeByte, writeShort, writeInt, ...

Aquesta classe no té les funcions next, nextLine, print, println ni printf.

Altres mètodes útils:

  • read(byte[] b): llegeix com a màxim b.length bytes del fitxer i els guarda a b.
  • write(byte[] b): escriu els bytes de b i els guarda al fitxer.
  • length(): obté la mida del fitxer en bytes.
  • setLength(): modifica la mida de l'arxiu: si és inferior a l'actual, trunca l'arxiu.

Llegir i escriure text (avançat)

El problema dels textos és que cal codificar-los (excepte que només s'utilitzin caràcters ASCII, cosa poc habitual actualment).

Depenent del tipus de codificació, un mateix text poc ocupar més o menys bytes, i s'ha de saber quina codificació s'ha utilitzat al guardar-lo per poder-lo llegir correctament.

Conjunts estàndard de codis de caràcters en Java (charsets)

Una forma de guardar dades que continguin text i altres valors en forma de registres amb camps de mida fixa pot ser la següent:

  • Crear un array de bytes de mida suficient per guardar la mida màxima del camp de text.
  • Convertir el text a bytes amb la funció String.getBytes(charset).
  • Comprovar que l'array amb el text és més petit que la mida de l'array - 1.
  • Copiar l'array amb el text en l'altre array.
  • Guardar aquest array.

RandomAccessFile raf = new RandomAccessFile(f, "rw");

String s = "Hola món!";
byte[] b = new byte[maxSize];
byte[] bs = s.getBytes(StandardCharsets.UTF_8);

if (bs.length > b.length - 1) {
    System.out.println("Error: text massa llarg");
    // throw new Exception("Error: text massa llarg");
    return;
}

System.arraycopy(bs, 0, b, 0, bs.length);
raf.write(b);

Per llegir el camp de text cal:

  • Crear un array de bytes de mida suficient per guardar la mida màxima del camp de text.
  • Llegir el nombre de bytes corresponent.
  • Crear un String a partir de l'array de bytes i la codificació amb new String(bytes, charset).
  • Retallar el text agafant des de l'inici fins que trobi un 0 (si no troba cap 0, no retalla).

RandomAccessFile raf = new RandomAccessFile(f, "r");

byte[] b = new byte[maxSize];
raf.read(b);
String s = new String(b, StandardCharsets.UTF_8);
int z = s.indexOf((char)0);
if (z >= 0) s = s.substring(0, z);
System.out.println(s);

Lectura i escriptura seqüencial

Quan s'obre un arxiu per llegir i/o escriure utilitzant la classe RandomAccessFile, l'apuntador se situa al principi de l'arxiu.

Cada cop que es llegeix o s'escriu una dada, el punter avança els bytes corresponents.

Accés relatiu a les dades

Si es coneix l'estructura de l'arxiu (la mida de cada "registre" i "camp"), es pot saber el nombre de registres que conté (midaArxiu / midaRegistre) i accedir directament als registres i camps.

Això permet, entre altres coses, no haver de carregar tota la informació en memòria per modificar-la, processar-la i tornar-la a escriure en el mateix arxiu.

Les funcions que permeten treballar amb accés relatiu són:

  • seek(): situa el punter en una posició determinada.
  • skipBytes(): salta cap endavant un número enter de bytes.
  • getFilePointer(): obté la posició actual del punter.
