Traducció del Model a BD relacional

Traducció de classes a taules (objectes a registres)

La forma com es guarden les dades en una BD relacional i com es guarden en memòria (especialment quan es treballa amb objectes), no té res a veure, però cal buscar una forma de traduir un model a l'altre perquè, actualment, la majoria de dades es guarden en BD relacionals i molts programes que accedeixen a aquestes dades estan fets utilitzant la programació orientada a objectes.

Classes amb dades primitives

Aquest cas és el més simple:

  • Cada classe es tradueix en una taula.
  • Cada atribut privat es correspon amb un camp de la taula (columnes).
    Si cal, s'afegeix un atribut que identifiqui cada objecte de forma exclusiva.
  • Cada objecte es transforma en un registre de la taula (files).
Exemples

Classe Producte

  • identificador (String)
  • descripció (String)
  • preu (float)

Clase Client

  • nif
  • nom
  • cognoms
  • adreça
  • telèfon

Classes amb llistes (associacions 1..n)

Aquest cas es transforma en dues taules:

  • La classe principal es transforma en una taula de la forma vista anteriorment.
  • La classe que correspon als objectes de la llista es transforma en una taula igual que abans.
    • En aquesta segona taula s'afegeix un camp pels identificadors dels l'objectes de la classe principal.
Exemple

Classe Examen

  • identificador (String)
  • llistaExercicis (List<Exercici>)

Classe Exercici

  • enunciat (String)
  • puntuació (float)

Se suposa que cada exercici només estarà en un examen.

Classes amb associacions n..m

En aquest cas, a més de crear dues taules principals, una per cada classe, cal afegir una tercera amb els identificadors de les dues taules.
En alguns casos, també s'afegeixen altres atributs.

Exemple

Classe Factura

  • identificador (integer)
  • data (DateTime)
  • client (Client)
  • baseImposable (float)
  • iva (float)
  • importIva (float)
  • total (float)
  • llistaArticles (List<Article>)

Classe Article

  • identificadorProducte (String)
  • quantitat (integer)
  • descompte (float)
  • import (float)

En aquest cas, les taules principals contenen les dades de les factures i dels productes.
La taula auxiliar contindrà:

  • identificadorFactura (integer)
  • identificadorProducte (String)
  • quantitat (integer)
  • descompte (float)
  • import (float)

Herència

Hi ha dues possibilitats:

  • Fer una taula per cada classe de la que es puguin crear objectes.
    Pot ser complicat realitzar determinades consultes.
  • Fer una única taula amb tots els atributs de totes les classes.
    Alguns camps de determinats registres no contindran cap dada.
Exemple

Classe abstracta Membre

  • nif
  • nom
  • telèfon
  • email

Classe Professor

  • titulació
  • departament
  • càrreg

Classe Alumne

  • dataNaixement
  • cicle
  • curs

La taula Membres inclourà els atributs de la classe Membre més els de Professor més els d'Alumne.

Traducció dels tipus de dades

boolean

La majoria de BD relacionals no tenen el tipus booleà.

Si és el cas, i depenent de cada BD, es pot substituir pel tipus BIT, TINYINT, CHAR(1) o NUMBER(1).

Text

El tipus char es tradueix a CHAR(1).

El tipus String es pot traduir a TINYTEXT, CHAR(n), VARCHAR(n), o LONG VARCHAR(n).

CHAR(n) completa amb espais si el text no ocupa la mida completa. Els altres, no.

Els literals de text en SQL es posen entre cometes simples.

Valors numèrics

El tipus byte equival a TINYINT (8 bits: -128 a 127).

El tipus short equival a SMALLINT (16 bits: -32768 a 32767).

El tipus int equival a INTEGER (32 bits).

El tipus long equival a BIGINT (64 bits).

El tipus float equival a REAL (32 bits).

El tipus double equival a DOUBLE (64 bits).

Data i hora

Els tipus nadius de Java per gestionar dates i hores no s'adapten bé als tipus que s'utilitzen en SQL (DATE, TIME i TIMESTAMP).

Per això cal utilitzar java.sql.Date, java.sql.Time i java.sql.Timestamp.

Altres

Per guardar dades binàries (en Java byte[ ]), es poden utilitzar BINARY(n), VARBINAY(n), BLOB(n)...
