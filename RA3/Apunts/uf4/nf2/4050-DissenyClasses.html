Disseny amb classes

Disseny i implementació d'un programa amb classes

El primer problema consisteix en identificar els objectes necessaris per emmagatzemar i gestionar les dades (aixó donarà lloc a les classes d'objectes).
Es pot pensar que cada tipus d'objecte equival a una taula en una base de dades, i cada objecte creat és equivalent a un registre de la taula.

Un cop identificats els tipus d'objectes, cal determinar els atributs i mètodes per cada tipus.
Els atributs serien els camps de la taula, mentre que els mètodes han de servir per obtenir (getters), modificar (setters) i fer altres operacions amb els valors dels atributs de cada objecte.

Després cal pensar les classes que gestionaran l'aplicació (classes amb atributs i mètodes estàtics).
En el cas de les classes de gestió, normalment s'aplica l'esquema Model-Vista-Controlador.

En el Model és on se situaran i gestionaran els conjunts d'objectes amb les dades de l'aplicació.
En el Controlador i en la Vista es posaran els objectes per rebre i mostrar informació a l'usuari (botons, camps de text, imatges, finestres amb llistes o taules...).

Disseny de les classes

El millor és començar per dissenyar les classes més generals i acabar amb les més concretes, intentant localitzar atributs i mètodes comuns a diferents tipus d'objectes i posant-los en les superclasses.

És recomanable utilitzar alguna eina per fer gràfics UML.

Símbols i tipografia UML pel disseny de classes

Cada classe es dibuixa en un requadre amb 3 parts:

  • Nom (part superior)
  • Atributs (part central)
  • Mètodes (part inferior)

Si una classe o un mètode son abstractes, s'ha de posar el nom en cursiva.

En el cas dels atributs cal indicar:

  • Els modificadors d'accés
    • static (subratllat)
    • public (+)
    • protectec (#)
    • package (per defecte, sense modificador) (~)
    • private (-)
  • El nom i el tipus (int, String, Classe, llista...) separats per :

En el cas dels mètodes, a més, cal especificar:

  • el nom i el tipus de cada paràmetre entre parèntesis i separats per :
  • el tipus del valor de retorn al final del tot i separat per :

Exemples d'atributs

+FILES: int   (public static final int FILES;)

-apotema: double   (private double apotema;)

~alumnes: llista Alumne   (Alumne[] alumnes;)

Exemples de mètodes

+convertPreu(preu: float): String   (public static String convertPreu(float preu);)

~calcularArea(): double   (abstract double calcularArea();)

#calcHipo(c1: double, c2: double) : double   (protected double calcHipo(doucle c1, double c2);)

Modificadors d'accés

Atributs

En els atributs, s'ha d'intentar que siguin el més restrictius possible sense que això impliqui una creació innecessària de getters i setters.

En la majoria de cassos, el mès convenient serà no posar modificador, suposant que, si hi ha subclasses, estaran en el mateix paquet.
Això permetrà que es pugui accedir lliurament als atributs des de les classes del mateix paquet.
Només caldrà posar getters i/o setters en els atributs que s'hagin de poder accedir des d'altres paquets.

Si algun atribut requereix validació abans de ser modificat sí que serà convenient posar-lo privat i crear el corresponent getter i setter amb les verificacions necessàries.

Mètodes

En general, els mètodes seran públics, exceptuant els que siguin mètodes auxiliars que només s'utilitzen en la mateixa classe o des de les subclasses o classes del mateix paquet.
En aquests casos s'haurà de de valorar si posar-los privats, protegits o per defecte.

Subclasses i interfícies

Per indicar que una classe és subclasse d'una altra, es posarà una fletxa de la subclasse a la classe.

Les interfícies es dibuixen igual que les classes però posant al davant del nom <<interface>>

Per indicar que una classe implementa una interfície, s'unirà la classe amb la interfície utilitzant una fletxa amb línia discontínua apuntant de la classe a la interfície.

Classes estàtiques o per un objecte únic

Les classes que no s'han d'instanciar (perquè només cal un objecte d'aquest tipus, per exemple la Vista), contindran atributs i mètodes estàtics.

Classes per crear objectes

Les classes que han de servir per crear objectes, contindran principalment atributs i mètodes no estàtics.

Implementació de les classes

La implementació també hauria de començar per les classes més generals i acabar amb les més concretes.

A més d'implementar cada classe, convé implementar també una classe per provar-la.

Mètodes per obtenir informació

A part dels mètodes getters, que normalment s'utilitzen per obtenir una sola dada, es poden crear altres mètodes per obtenir més dades de cop o dades calculades a partir d'altres atributs.

Un mètode que acostumen a oferir la majoria de les classes de Java és toString().
Aquest mètode retorna un String amb informació de l'objecte, i Java l'utilitza quan necessita transformar un objecte en un text.
Cada classe pot implementar-lo com més li convingui (si la classes no implementa aquest mètode i s'intenta printar un objecte, mostrarà la seva referència):

public class Persona {
    String nom;
    int edat;

    public Persona(String n, int e) {
        nom = n;
        edat = e;
    }

    @Override
    public String toString() {
        return nom + " " + edat;
    }
}

Persona p = new Persona("Mary", 18);
System.out.println("Alumne: " + p);

També es poden crear altres mètodes per retornar la informació en un format determinat:

public class Persona {
    ...
   
    public String getInfo() {
        return "Nom: " + nom + "\nEdat: " + edat;
    }
}

Persona p = new Persona("Mary", 18);
System.out.println(p.getInfo());

No és convenient que la mateixa classe implementi mètodes per mostrar la informació de l'objecte.
D'aquesta funció s'han d'encarregar les classes de la Vista, que hauran de cridar als getters, toString o altres mètodes de la classe per obtenir la informació i mostrar-la de la forma apropiada.
