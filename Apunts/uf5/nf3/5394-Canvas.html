Canvas ref. (Java SE 17)

Aquest tipus de component consisteix en una àrea rectangular sobre la qual es pot dibuixar.

Habitualment s'utilitza en jocs i animacions perquè permet utilitzar la tècnica del Double Buffer.
Aquesta tècnica consisteix en dibuixar la imatge en segon pla i mostrar-la quan s'ha acabat de dibuixar, de forma sincronitzada amb l'actualització de la pantalla.
D'aquesta forma s'evita el flickering (parpalleig) de les imatges animades.

El doble buffer s'ha de configurar en l'objecte Canvas però un cop s'ha ajustat i mostrat la finestra.
Si es fa abans, generarà l'excepció IllegalStateException: Component must have a valid peer.

BufferStrategy strategy;

public void crearDobleBuffer() {
    setIgnoreRepaint(true);      // Només es redibuixa amb la comanda strategy.show()
    createBufferStrategy(2);     // Crea el doble buffer
    strategy = getBufferStrategy();   // Objecte que gestiona el doble buffer
}

public static void main(String[] args) {
    CanvasJoc canvas = new CanvasJoc();    // Crear Canvas
    JFrame f = new JFrame("DobleBuffer");  // Crear finestra
    f.getContentPane().add(canvas);        // Afegir Canvas al panell principal
    f.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
    f.setResizable(false);
    f.pack();
    f.setVisible(true);
    canvas.crearDobleBuffer();             // Crear doble buffer
    canvas.jugar();
}

I per dibuixar en el buffer corresponent:

public void dibuixar() {
    Graphics2D g = (Graphics2D) strategy.getDrawGraphics();
    super.paint(g);     // Esborra el fons

    // Dibuixar la imatge
    // ...

    g.dispose();        // Allibera els recursos que utilitza Graphics
    strategy.show();    // Mostra la imatge del buffer sobre el què s'ha dibuixat
}

Relacionat amb els jocs i les animacions, també cal saber com generar imatges amb una certa freqüència.

Una forma senzilla pot ser utilitzar el mètode Thread.sleep(milliseconds) dins d'un bucle:

public void animacio() {
    while (true) {
        processar();
        dibuixar();

        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }
    }
}

El problema del mètode anterior és que, depenent del què es trigui en processar i dibuixar, el temps entre una imatge i la següent pot ser variable.

Un sistema millor és utilitzat Timer.scheduleAtFixedRate(TimerTask t, delay, period).

public void animacio() {
    java.util.Timer timer = new java.util.Timer();
    timer.scheduleAtFixedRate(
        new TimerTask(){
            @Override
            public void run(){    // Tasca que s'ha d'executar repetidament
                processar();
                dibuixar();
            }
        },
        0,     // Retard de la primera execució
        100    // Temps entre l'inici de cada execució
    );
}

El paquet java.swing també conté una classe Timer, però la que s'ha d'utilitzar és la del paquet java.util, per això no n'hi ha prou amb posar Timer: cal especificar java.util.Timer.
