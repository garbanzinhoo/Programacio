Excepcions en Java

Errors i excepcions

Durant l'execució d'un programa es poden produir errors deguts a una mala programació, dades d'entrada incorrectes o, senzillament, a situacions inesperades o impredictibles.

Java distingeix entre errors irrecuperables (provoquen la finalització bruca del programa) i excepcions.
Aquestes últimes sí que es poden preveure, detectar i gestionar per evitar que el programa s'aturi.

Quan es produeix una excepció, s'envia un objecte d'alguna classe derivada de Exception.
En Java hi ha dos grans tipus (subclasses) d'excepcions:

  • RunTimeException: no és obligatori tractar-les (per exemple, IndexOutOfBoundsException, NullPointerException o ArithmeticException).
  • Totes les altres s'han de tractar. Si no es fa, el compilador donarà error i no compilarà el programa.

Estructura per gestionar les excepcions

Per ajudar-nos en aquesta tasca, Java i molts altres llenguatges proporcionen la següent estructura:

try {
  ...              // Bloc amb codi que pot generar excepcions
} catch (exc) {
  ...              // Bloc amb el codi que tracta l'excepció
} finally {
  ...              // Bloc amb codi que s'executarà sempre
}

Pot haver-hi més d'un bloc catch (un per cada tipus d'excepció que es vulgui tractar).
El bloc finally no és obligatori, però és recomanable per tancar recursos.

  • Bloc try: conté el codi que pot provocar excepcions que facin aturar el programa.
    Si no es produeix cap error, s'ignora el bloc catch.
    En el moment que es produeix un error, ignora el codi restant de dins del bloc try, es passa la informació de l'error a un bloc catch que pugui tractar l'excepció i executa el seu codi.
    Finalment, si existeix un bloc finally, executa el seu codi.
  • Blocs catch: contenen el codi que s'executarà si es produeix un error dins del bloc try.
    Serveixen per tractar l'excepció (intentar solventar el problema evitant que el programa finalitzi degut a l'error).
    Se li passa un objecte de la classe Exception o derivada amb informació sobre l'excepció.
    L'execució continuarà amb el bloc finally (si existeix).
  • Bloc finally: conté el codi que s'executarà tant si es produeix un error com si no.
    Fins i tot s'executa si en el bloc try o en el bloc catch hi ha un return!!!
    L'única forma d'evitar que s'executi el bloc finally és cridar el mètode System.exit().
    La principal utilitat és tancar el programa de la forma més correcta possible en cas que no es pugui solventar l'error.
    I si no s'ha produït cap error o s'ha pogut solucionar, per realitzar tasques que s'han de realitzar tant si hi ha errors com si no (inicialitzar variables, tancar arxius oberts, alliberar recursos...).
    També pot servir per saber fins on ha arribat l'execució del bloc try. Per exemple, si en el try hi ha un bucle, es pot enviar a la consola el valor de la variable de control en el moment de l'error.
    Després d'executar el seu codi, si l'excepció ha estat capturada i no es produeix cap error, el programa continua normalment. Si no s'ha capturat l'excepció, aquesta es propaga al mètode superior.

Capturar i gestionar les excepcions

En Java, quan es produeix una excepció dins d'un bloc try, s'envia un objecte d'alguna classe derivada de Exception. Aquest objecte és el paràmetre que arriba al bloc catch encarregat de gestionar l'excepció.

Aquests objectes tenen mètodes que poden ser útils per esbrinar el motiu i el lloc on s'ha produït l'excepció:

  • toString()
  • getMessage()
  • printStackTrace(): mostra en la terminal d'error informació detallada.

Delegar la gestió de les excepcions

Si un mètode no vol tractar les excepcions que es poden produir en el seu codi i deixar que les tracti un mètode superior, pot indicar-ho en la seva definició amb la paraula throws seguida de les excepcions de les quals vol delegar el seu tractament:

static void llegirArxiu() throws FileNotFoundException, IOException {
    File f = new File("./arxiu.bin");
    RandomAccessFile raf = new RandomAccessFile(f, "r");
    raf.readInt()
    raf.close();
}

Llançar una excepció

Es pot fer que el programa, quan detecti un error, llanci una excepció per indicar una situació anòmala.

Per llançar una excepció s'utilitza la paraula reservada throw seguida d'un objecte de tipus Exception o derivada d'aquesta.
Un dels constructors de la classe Exception i derivades accepta un String com a paràmetre:

throw new Exception("Error indeterminat");
throw new IllegalArgumentException("Error en un dels arguments");

El mètode dins del qual es llança una excepció haurà de tractar-la o delegar el seu tractament.
