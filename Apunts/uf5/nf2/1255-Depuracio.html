Gestió dels errors (try, cath, finally i throw)

Referència de l'objecte Error

Durant l'execució d'un programa es poden produir errors deguts a una mala programació, dades d'entrada incorrectes o, senzillament, a situacions inesperades o impredictibles.

Per evitar que el programa quedi aturat degut a un error, s'ha d'intentar preveure, detectar i processar adequadament els errors que es puguin produir.

Per ajudar-nos en aquesta tasca, JavaScript i molts altres llenguatges proporcionen la següent estructura:

try {                // Bloc amb codi que pot contenir errors
  ...
} catch(err) {       // Bloc amb el codi que tracta l'error
  ...
} finally {          // Bloc amb codi que s'executarà sempre
  ...
}

Mai s'ha de posar un try/catch dins d'una funció recursiva.
En aquests casos, s'ha de posar en la funció que crida a la funció recursiva.

Per defecte, el tipus de missatge que envia JavaScript quan troba un error, és un objecte de tipus Error.
Aquest és el paràmetre que li arriba al bloc catch.
Es pot trobar informació més detallada en l'enllaç del principi del capítol.

Aquest objecte té dos atributs:

  • name: conté el nom de l'error, que pot ser un dels següents:
    • EvalError
    • RangeError
    • ReferenceError
    • SyntaxError
    • TypeError
    • URIError
  • message: un string que conté més informació sobre l'error.

Per tant, dins del bloc catch es pot posar una comanda com la següent per mostrar l'error:

console.log(err.message);

El bloc try és obligatori.
Els blocs catch i finally són opcionals però s'ha de posar al menys un dels dos.
Si es posa el bloc catch, el bloc finally és innecessari: el seu codi es pot posar després de l'estructura de control (a menys que dins del bloc catch es pugui produir un altre error o rellançar el què s'havia produït en el bloc try).

  • Bloc try: conté el codi que pot provocar errors que facin aturar el programa.
    Si no es produeix cap error, s'ignoren els blocs catch i finally i continua l'execució del programa.
    En el moment que es produeix un error, ignora el codi restant.
    Si existeix un bloc catch, li passa la informació de l'error i executa el seu codi.
    Si existeix un bloc finally, executa el seu codi.
  • Bloc catch: conté el codi que s'executarà si es produeix un error dins del bloc try.
    Serveix per tractar l'error (intentar solventar el problema evitant que el programa s'aturi).
    Se li passa un paràmetre amb informació sobre l'error que s'ha produït.
    L'execució continuarà amb el bloc finally (si existeix).
    Si no es posa aquest bloc i es produeix un error, el programa finalitzarà amb un error després d'executar el bloc finally (si existeix).
  • Bloc finally: conté el codi que s'executarà tant si es produeix un error com si no.
    Fins i tot s'executa si en el bloc try o en el bloc catch hi ha un return!!!
    La principal utilitat és tancar el programa de la forma més correcta possible en cas que no es pugui solventar l'error. I si no s'ha produït cap error o s'ha pogut solucionar, per realitzar tasques que s'han de realitzar tant si hi ha errors com si no (inicialitzar variables, tancar arxius oberts...).
    També pot servir per saber fins on ha arribat l'execució del bloc try. Per exemple, si en el try hi ha un bucle, es pot enviar a la consola el valor de la variable de control en el moment de l'error.
    Després d'executar el seu codi, si no s'ha produït cap error, el programa continua normalment.
    Si s'ha produït un error:
    • Si existeix el bloc catch, el programa continua l'execució normalment.
    • Si no existeix el bloc catch, el programa finalitza amb un error.

Dins del bloc try només s'hauria de posar codi que pugui generar excepcions.

Entendre la utilitat del "finally" en la gestió d'errors

Comanda throw

Aquesta comanda es pot utilitzar dins d'un bloc try (on en qualsevol lloc d'un programa) per comunicar que s'ha produït un error i sol·licitar un tractament.

L'execució continuarà en el bloc catch (si existeix) i/o amb el bloc finally (si existeix).

Cal indicar d'alguna forma el tipus d'error que s'ha produït, per exemple, amb un missatge de text:

throw new Error("Error indeterminat");      // Generar una excepció personalitzada

També es pot posar dins d'un bloc catch per rellançar l'error (indicar que no s'ha pogut solucionar).
En aquest cas, s'executarà el bloc finally (si existeix) i el programa acabarà amb error o serà processat per un altre estructura de control d'errors superior, si existeix (un try...catch que conté aquest).
